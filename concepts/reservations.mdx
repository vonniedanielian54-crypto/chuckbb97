Reservations secure a guest's spot at a venue. Track the `status` field to know where each booking stands.

## Lifecycle

```text
pending → confirmed → seated → completed
                    ↘ cancelled
```

| Status | Description |
|---|---|
| `pending` | Submitted, awaiting venue confirmation |
| `confirmed` | Venue accepted; guest has a guaranteed spot |
| `seated` | Guest has arrived and been seated |
| `completed` | Visit is over |
| `cancelled` | Cancelled by guest or venue |

<Note>
  Most reservations move from `pending` to `confirmed` in seconds. Some venues require manual review.
</Note>

## Reservation object

| Property | Type | Description |
|---|---|---|
| `id` | string | Unique identifier |
| `venue_id` | string | Reserved venue |
| `date` | string | `YYYY-MM-DD` |
| `time` | string | `HH:MM` (24-hour) |
| `party_size` | integer | Number of guests |
| `guest_name` | string | Primary guest's full name |
| `guest_email` | string | Confirmation email |
| `guest_phone` | string | Contact number |
| `status` | string | Current lifecycle state |
| `notes` | string | Special requests (500 char max) |
| `created_at` | string | ISO 8601 timestamp |

```json
{
  "id": "res_xyz789",
  "venue_id": "venue_abc123",
  "date": "2025-02-14",
  "time": "19:30",
  "party_size": 4,
  "guest_name": "Jordan Ellis",
  "guest_email": "jordan.ellis@example.com",
  "guest_phone": "+12125550192",
  "status": "confirmed",
  "notes": "Anniversary, please prepare a dessert surprise.",
  "created_at": "2025-01-20T14:22:10Z"
}
```

## API

```bash
# Create
curl -X POST https://api.kdllc.com/v1/reservations \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"venue_id":"venue_abc123","date":"2025-02-14","time":"19:30","party_size":4,"guest_name":"Jordan Ellis","guest_email":"jordan.ellis@example.com","guest_phone":"+12125550192"}'

# Retrieve
curl https://api.kdllc.com/v1/reservations/res_xyz789 \
  -H "Authorization: Bearer YOUR_API_KEY"

# Update
curl -X PUT https://api.kdllc.com/v1/reservations/res_xyz789 \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"party_size":6,"time":"20:00"}'

# Cancel
curl -X DELETE https://api.kdllc.com/v1/reservations/res_xyz789 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

<Note>
  If a requested modification slot is unavailable, the original reservation is preserved and an error is returned.
</Note>

## Policies

### Cancellation

Each venue sets a cancellation deadline (see `policies.cancellation` on the venue). Cancellations after the deadline may incur a fee.

<Warning>
  Cancellations submitted after the venue's deadline are non-refundable.
</Warning>

### Modifications

Guests can modify a confirmed reservation up to the venue's modification cutoff via `PUT /reservations/{id}`.

### No-shows

If a guest doesn't arrive within the venue's no-show window (typically 15 to 30 minutes late), the venue may mark the booking as a no-show and charge a fee.

<Tip>
  Send an automated reminder 24 hours before the reservation with a one-click cancellation link to reduce no-shows.
</Tip>

## Special requests

Use the `notes` field for preferences, allergies, accessibility needs, or celebrations. Common examples:

- `"Guest has a severe nut allergy"`
- `"Birthday, please have candles on the dessert"`
- `"Prefer a booth or window table"`
- `"Wheelchair-accessible seating required"`

<Note>
  Notes are passed to venue staff but not guaranteed. For critical requirements, guests should contact the venue directly.
</Note>
