KD LLC sends notifications at every meaningful moment in the reservation lifecycle — when a booking is confirmed, when a reminder is due, when a cancellation is processed, and when an event is updated. You control which channels receive which messages and how quickly they arrive. Navigate to **Settings → Notifications** to manage all of these preferences.

## Notification Channels

KD LLC supports four notification channels. You can enable any combination of them independently for different event types.

| Channel | Best For | Setup Required |
|---|---|---|
| **Email** | Confirmations, receipts, detailed itineraries | None — active by default |
| **SMS** | Time-sensitive reminders and cancellations | Phone number verification |
| **Push (Mobile App)** | Real-time alerts on iOS and Android | KD LLC app installed |
| **Webhook** | Server-to-server automation and integrations | Public URL configured |

## Email Notifications

Email is enabled for all accounts and requires no additional setup. To customize which events trigger emails, go to **Settings → Notifications → Email**.

### Triggering Events

Toggle email delivery on or off for each of the following events:

- **Reservation Confirmed** — Sent immediately when a reservation is accepted
- **Reservation Reminder** — Sent before the reservation (timing is configurable; see [Reminder Timing](#reservation-reminder-timing))
- **Reservation Cancelled** — Sent when a guest or operator cancels a booking
- **Reservation Modified** — Sent when date, time, or party size changes
- **Event Published** — Sent to followers when a venue publishes a new event
- **Event Cancelled** — Sent to ticket holders when an event is called off

### Customizing Email Templates

Operators can customize the content of confirmation and reminder emails to reflect their venue's branding:

<Steps>
  <Step title="Open Email Templates">
    Navigate to **Settings → Notifications → Email → Templates**.
  </Step>
  <Step title="Select a template">
    Choose the template you want to edit (for example, **Reservation Confirmed**).
  </Step>
  <Step title="Edit the content">
    Update the subject line, header image, and body copy using the visual editor.
  </Step>
  <Step title="Preview and save">
    Click **Preview** to review a rendered sample, then click **Save Template** to apply the changes to all future emails.
  </Step>
</Steps>

<Tip>
Include your venue's cancellation policy and a direct link to the reservation management page in your confirmation email template to reduce inbound support requests.
</Tip>

## SMS Notifications

SMS notifications deliver short, time-sensitive messages directly to a guest's or operator's mobile number.

### Enabling SMS

<Steps>
  <Step title="Open SMS settings">
    Navigate to **Settings → Notifications → SMS** and toggle **Enable SMS Notifications** on.
  </Step>
  <Step title="Verify your phone number">
    If you have not yet verified a phone number, enter one when prompted and enter the 6-digit verification code you receive to complete verification.
  </Step>
</Steps>

<Note>
Standard carrier messaging rates may apply to guests who receive SMS notifications. KD LLC does not charge separately for outbound SMS within supported regions.
</Note>

### Choosing SMS Events

Once SMS is active, select which events trigger a text message. At minimum, enabling **Reservation Reminder (2-hour)** is recommended for time-sensitive venues.

## Reservation Reminder Timing

KD LLC supports two configurable reminder windows. Both can be enabled simultaneously on any channel.

| Reminder | Default Timing | Channels Supported |
|---|---|---|
| **24-Hour Reminder** | 24 hours before reservation time | Email, SMS, Push |
| **2-Hour Reminder** | 2 hours before reservation time | Email, SMS, Push |

### Configuring Reminder Timing

To adjust when reminders are sent:

<Steps>
  <Step title="Open Reminders settings">
    Go to **Settings → Notifications → Reminders**.
  </Step>
  <Step title="Choose a reminder">
    Find the reminder you want to configure (**24-Hour** or **2-Hour**).
  </Step>
  <Step title="Set the offset">
    Use the **Offset** dropdown to change the lead time. Available options: 1 h, 2 h, 4 h, 6 h, 12 h, 24 h, 48 h.
  </Step>
  <Step title="Select channels and save">
    Toggle the channels (Email, SMS, Push) you want to use for each reminder, then click **Save**.
  </Step>
</Steps>

<Note>
If a reservation is created less than 24 hours before the reservation time, the 24-hour reminder is skipped automatically and only the 2-hour reminder fires (if applicable).
</Note>

## Webhook Notifications

Webhooks allow KD LLC to push real-time event data to your server via HTTP POST requests. This is useful for custom integrations, automated dashboards, or any downstream system that needs to react to reservation changes programmatically.

### Setting Your Webhook URL

<Steps>
  <Step title="Open Webhooks settings">
    Navigate to **Settings → Notifications → Webhooks** and click **Add Endpoint**.
  </Step>
  <Step title="Enter your endpoint URL">
    Enter the publicly accessible HTTPS URL that will receive the payloads.
  </Step>
  <Step title="Select event types">
    Choose the event types you want to subscribe to (see the table below).
  </Step>
  <Step title="Save the endpoint">
    Click **Save Endpoint** to activate delivery.
  </Step>
</Steps>

### Subscribable Event Types

| Event | Triggered When |
|---|---|
| `reservation.confirmed` | A reservation is accepted by the venue |
| `reservation.cancelled` | A reservation is cancelled by either party |
| `reservation.modified` | Date, time, or party size on a reservation changes |
| `event.published` | A venue publishes a new public event |
| `event.cancelled` | A published event is cancelled |

### Sample Webhook Payload

The following is a sample POST body for a `reservation.confirmed` event:

```json
{
  "event": "reservation.confirmed",
  "timestamp": "2024-02-10T14:30:00Z",
  "data": {
    "reservation_id": "res_xyz789",
    "venue_id": "venue_abc123",
    "guest_name": "Jane Smith",
    "date": "2024-02-14",
    "time": "7:30 PM",
    "party_size": 4
  }
}
```

All payloads follow this envelope structure: a top-level `event` string, an ISO 8601 `timestamp`, and a `data` object containing event-specific fields.

### Verifying Webhook Signatures

Every webhook request from KD LLC includes an `X-KD-Signature` header containing an HMAC-SHA256 signature of the raw request body, signed with your endpoint's secret key. Always verify this signature before processing the payload to ensure the request genuinely originated from KD LLC and was not tampered with in transit. Your endpoint secret is displayed once when you create the webhook endpoint — store it securely.

To verify the signature, compute `HMAC-SHA256(raw_body, your_secret)` and compare it to the value in `X-KD-Signature`. Reject any request where the values do not match.

<Warning>
Do not parse or modify the request body before computing the HMAC signature. Any transformation — including JSON pretty-printing or whitespace normalization — changes the byte sequence and causes every signature check to fail.
</Warning>
